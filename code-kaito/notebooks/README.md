# Worked examples of learned quotient dynamics

- [Sphere flow](01_sphere.ipynb) explains the height quotient, learned interval dynamics, and circle-fiber contributions to local indices.
- [O(3) flow](02_o3_flow.ipynb) explains positive-gain coordinates, two-dimensional quotient dynamics, and sphere-fiber contributions.
- [Reduced attitude control](03_attitude.ipynb) reproduces six saved sphere models, compares native and aggregated interval graphs, and draws sphere preimages and reconstructed indices.

Read each notebook from top to bottom. Each introduces the system, defines map domains and codomains, explains the model and numerical settings, and describes how to read the figures. Saved outputs are included. Figures are generated by the notebook or its documented replay functions, not extracted from manuscript pages.

For Examples 1 and 2, follow the [environment setup](../README.md#run-locally), select `code-kaito/.venv`, and run every cell. Their fitting cells load saved checkpoints by default.

Example 3 uses the same notebook kernel and launches a separate Python 3.13 replay interpreter, preserving the numerical versions used by the upstream experiment. From `code-kaito/`, install it once:

```bash
uv venv .venv-attitude --python 3.13
uv pip install --python .venv-attitude/bin/python -r ../code/requirements.txt
```

Keep the complete repository checkout, including `code/examples/example3/periodic/reference/`. Install Graphviz and Poppler as described in `code/README.md`. Run All regenerates physical data, loads six saved checkpoints without training, recomputes the native and grouped graphs, and verifies them against the frozen results. Every run gets a fresh directory under `build/notebooks/attitude/`. Full replay logs, numerical arrays, and editable PDF/SVG figure sources remain there.

The attitude model is supervised toward the known thrust axis and trained on an invariant subsystem. Its graph checks and sampled sphere preimages do not certify attracting regions for the full quadrotor state.

Examples 1 and 2 retain their saved `code-kaito` experiment configurations. Bernardo’s numbered workflows in `code/examples/` are separate experiments, so their checkpoints and training settings are not interchangeable. Example 3 explicitly replays the periodic-control workflow in `code/examples/example3/periodic/`.
